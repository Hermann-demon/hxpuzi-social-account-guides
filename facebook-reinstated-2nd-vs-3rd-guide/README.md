## 到手首登验收清单（24 小时内完成）

![首登验收清单示意](images/gen-acceptance-checklist.jpg)

### 1. 下单前核对规格
- 看清是二解还是三解、地区、注册年份、交付字段，以及「包首登 / 5天内售后」等条款。
- 商品页写明：Facebook 账号除标题或规格另有说明外，**只保证 24 小时内首次登录成功**；先买 1–2 个走通流程再加量。

### 2. 拆分并保存交付字段
- 常见格式：`UID | 密码 | 2FA | 邮箱 | 邮箱密码 | Cookie`（以所购规格为准；部分规格还有辅助邮箱）。
- 交付原文和订单号存进密码管理器或加密笔记；**截图时遮住密码、2FA 密钥、邮箱密码和 Cookie**。
- 别把**邮箱密码**当成 Facebook 密码——这是「密码错误」最常见的原因之一。

### 3. 准备登录环境
- 使用稳定、干净的网络与设备；首登期间不要频繁切换网络，一次只登录一个账号。
- 首登方式按商品页说明进行（多数 FB 规格建议优先使用随货 Cookie / 缓存登录），操作见 [官网CK登录说明](https://hxpuzi.com/article/fb-ck-login/?utm_source=github)。Cookie 是密码级敏感数据，不要贴到来源不明的网站或扩展。
- 先把 2FA 密钥导入本地验证器，并开启手机**自动日期与时间**（见 [2FA密钥登录教程](../2fa-key-login-guide/)）。

### 4. 从官方入口首次登录
- 手动输入 facebook.com 或使用官方 App；用 UID / 邮箱 + 密码登录。
- 要求双重验证时，填验证器**当前**生成的 6 位码；默认要短信时点「尝试其他方式」选身份验证应用。

### 5. 逐项验收并留证
| 验收项 | 怎么核对 | 留什么证据 |
| --- | --- | --- |
| UID / 资料页 | 交付 UID 与登录后的资料页一致 | 资料页截图（带时间） |
| 规格属性 | 注册年份、地区、好友数是否符合所购规格 | 对应页面截图 |
| 2FA | 验证器生成的码能通过验证 | 通过后的页面截图（遮住密钥） |
| 邮箱 | 邮箱 + 邮箱密码能在官方入口登录、能收信 | 收件箱截图（遮住密码） |
| 账号状态 | 首页能正常打开，无限制提示 | 首页截图与时间 |

更完整的字段说明见官网 [Facebook交付格式与首登验收](https://hxpuzi.com/article/facebook-uid-2fa-email-cookie-delivery-acceptance-guide/?utm_source=github)。

### 6. 验收通过后再安全接管
1. 修改 Facebook 密码；含邮箱的规格同步修改邮箱密码。
2. 在「密码和安全」里重置 2FA，扫描**新**密钥，让旧密钥作废；离线保存恢复码。
3. 检查登录位置，退出不认识的会话，撤销不需要的第三方授权。
4. **一次只改一项**，每改完确认仍能正常登录，再做下一项。

## 首登失败排查表

| 现象 | 常见原因 | 怎么处理 |
| --- | --- | --- |
| 提示密码错误 | 字段拆错（用了邮箱密码）、复制多了空格或全角符号 | 从交付原文重新复制对应字段；换回稳定网络后再试**一次**，不要连续重试 |
| 2FA 验证码无效 | 手机时间不同步、密钥带空格、码刚好过期 | 开启自动时间，去掉密钥空格，等新码出现再填 |
| 要短信或邮箱码 | 平台默认了其他验证方式 | 点「尝试其他方式」选身份验证应用；邮箱码去交付邮箱查收 |
| 出现身份确认页（checkpoint） | 新环境登录触发平台安全检查 | **停止操作**、不要反复提交；截图记录时间后联系售后。商品页写明：新环境出现人脸 / 证件 / 手机号验证属于平台环境风控，不在售后范围 |
| 邮箱登不上 | 邮箱密码与 FB 密码混淆，或邮箱要求额外验证 | 确认字段，用邮箱官方入口登录；仍失败就留证找售后 |

## 常见问题

**Q1：二次解限和三次解限是 Facebook 官方的说法吗？**  
不是。这是卖家对账号历史的标注：账号被限制后经审核恢复过几次。它不是 Meta 的官方等级。

**Q2：三解一定比二解更稳吗？**  
官网把三解定位为更耐用的老号档，但任何规格都不承诺长期不受限。按用途选，先少量测试。

**Q3：只要包首登，二解和三解售后一样吗？**  
基本一样：都是交付后约 24 小时内首次登录成功；「5天内售后一次」等额外条款只适用于标题里写明的规格。

**Q4：随货的 Cookie 一定要用吗？**  
不是必须，但多数 FB 商品页建议首登优先用 Cookie / 缓存登录。它属于敏感凭据，按 [官网CK登录说明](https://hxpuzi.com/article/fb-ck-login/?utm_source=github) 使用，验收后再用密码 + 2FA 的正常方式接管。

**Q5：登录后被要求验证身份，可以自己申诉吗？**  
官网规则写明：个人号权限受限请勿自行申诉，申诉后不在售后范围。遇到这种情况先停止操作，留证联系售后。
